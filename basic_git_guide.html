Git & GitHub Codespaces Guide

ISE 2530 Course Project

Recommended: Use GitHub Codespaces for this course. Codespaces allows you to work on the project entirely in your browser without installing Git, Python, or VS Code on your computer.

What is Git?

Git is a version-control tool used to keep track of changes made to project files. It allows multiple team members to contribute to the same project while maintaining a history of changes.

Your team's project is stored in a GitHub repository. Each team member can make changes and then share those changes with the team.

Pull → Edit → Save → Commit → Push

Option 1 — GitHub Codespaces (Recommended)

GitHub Codespaces provides a browser-based VS Code environment connected directly to your team's GitHub repository.

You do not need to install:

  • Git
  • VS Code
  • Python locally
  • Course dependencies locally

1. Open Your Team Repository

Open the GitHub repository assigned to your team.

2. Create a Codespace

  1. Click the green Code button.
  2. Select the Codespaces tab.
  3. Click Create codespace.
  4. Wait for the environment to load.

A browser-based VS Code window will open with the project files already available.

Each team member may use their own Codespace connected to the same team repository. You do not need to share one Codespace.

3. Get the Latest Team Changes

Before beginning work, open the terminal inside your Codespace and run: 

git pull

This downloads changes that your teammates have already pushed.

4. Edit Your Files

Use the file explorer on the left side of VS Code to open and edit your assigned files.

For Milestone 1, your team will mainly work with:

milestone_1/
├── dataset.xlsx
├── project_proposal.md
├── dataset_description.md
├── data_dictionary.md
├── decision_definition.md
└── feasibility_preview.md

Save your file using Ctrl + S or File → Save.

5. Check What You Changed

git status

Git will show the files you modified or added.

6. Add Your Changes

Add all changed files:

git add .

Or add one specific file:

git add milestone_1/project_proposal.md

7. Commit Your Changes

A commit records a snapshot of your work.

git commit -m "Complete project proposal"

Use a short message that explains what you completed.

Good examples:

git commit -m "Add dataset description"
git commit -m "Complete data dictionary"
git commit -m "Revise recurring decision"
git commit -m "Complete feasibility preview"

8. Push Your Changes

Push the committed work to the team's GitHub repository:

git push

Your teammates can now receive your changes by running:

git pull

Example — Three Students Working Together

Suppose a three-person team divides Milestone 1 work like this:

Student Example Responsibility
Student A project_proposal.md
Student B dataset_description.md and data_dictionary.md
Student C decision_definition.md and feasibility_preview.md

Student A might do:

git pull

# Edit project_proposal.md

git status
git add .
git commit -m "Complete project proposal"
git push

Before Student B continues working, Student B should run:

git pull

Student B will now have Student A's latest committed work.

Using VS Code Source Control Instead of Commands

You can also perform Git operations using the Source Control icon on the left side of your Codespace.

  1. Open Source Control.
  2. Review the files you changed.
  3. Stage your changes.
  4. Enter a commit message.
  5. Click Commit.
  6. Click Sync Changes or Push.

You may use either the terminal commands or the VS Code interface.

Avoiding Merge Conflicts

Try not to have multiple team members independently edit the same part of the same file at the same time.

Always begin your work with:

git pull

And finish meaningful work with:

git add .
git commit -m "Describe your changes"
git push
If Git reports a merge conflict: do not delete another team member's work simply to make the error disappear. Review the conflicting changes together and determine what the final content should contain.

Option 2 — Work Locally

If you prefer to work on your own computer instead of using Codespaces, you may install Git and clone the repository locally.

1. Install Git

Windows:

  1. Go to git-scm.com/download/win .
  2. Download and run the installer.
  3. The default installer options are normally sufficient.

macOS:

Open Terminal and run:

git --version

If Git is unavailable, macOS may prompt you to install the required developer tools.

Verify the installation:

git --version

2. Clone Your Team Repository

Copy the repository URL from your team's GitHub page and run:

git clone YOUR_TEAM_REPOSITORY_URL

Then enter the repository:

cd YOUR_REPOSITORY_FOLDER
Do not clone another team's repository or use the instructor starter repository as your working submission. Use the repository assigned to your team.

3. Use the Same Git Workflow

After cloning, the normal workflow is the same:

git pull

# Edit files

git status
git add .
git commit -m "Describe your changes"
git push

Important Rules

  • Run git pull before beginning new work.
  • Use clear commit messages that describe what you changed.
  • Commit after completing a meaningful piece of work.
  • Push your commits so your teammates can access them.
  • Avoid editing the same section of the same file simultaneously.
  • Do not create additional branches unless instructed.
  • Do not delete another student's work to resolve a conflict.
  • Make sure your final work appears in the team repository on GitHub.

Remember

PULL → EDIT → SAVE → ADD → COMMIT → PUSH

Your changes are not fully shared with your team until they have been committed and pushed to GitHub.
